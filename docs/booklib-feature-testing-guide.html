BookLib End-to-End Feature Testing Guide

Step-wise checklist for testing the platform after changes. Use this before deployment and again on production after migration/restart.

Web: https://booklib.in API: https://api.booklib.in/v1 Last updated: 2026-05-23
Pre-flight

Build, Migration, And Basic Smoke

Run these checks before testing user flows. If migration is skipped, the new book syllabus tables will not work.
  1. Run npm.cmd run build and confirm it passes.
  2. Run npm.cmd test and confirm all tests pass.
  3. Run API migrations on the target server: npm run migrate -w @booklib/api.
  4. Restart API and web processes.
  5. Open /health and confirm API responds.
  6. Open landing page, owner login, student login, and superadmin login once.
Auth

Login, Session, Google, Password

  1. Login as Superadmin and verify dashboard opens.
  2. Login as Owner and verify owner dashboard opens, not student/superadmin.
  3. Login as Student and verify student dashboard opens, not owner.
  4. Refresh browser and confirm session stays active.
  5. Close and reopen browser, confirm session remains active until logout.
  6. Check password eye button on every password field.
  7. Check forgot-password link on all login screens.
  8. Google login: owner/student should land on the correct role dashboard.
Navigation

Shell, Sidebar, Header, Drawers

  1. Open key owner pages: dashboard, admissions, roster, seats, attendance, payments, plans, coupons, listing, website, settings.
  2. Confirm sidebar does not move upward or overlay page content.
  3. Confirm global header has no duplicate page title/action clutter.
  4. Open forms and verify drawers open from right on desktop.
  5. On mobile, drawers open as usable full-screen/bottom-safe sheets.
  6. Confirm bottom nav never hides submit buttons or page bottom content.
Superadmin

Superadmin Control And Content

360 Control Center

  1. Open /superadmin/libraries.
  2. Search by library name, city, owner, status, and plan.
  3. Select a tenant and check overview, users, students, payments, seats, website, activity, danger tabs.
  4. Suspend tenant and verify owner access is blocked.
  5. Reactivate tenant and verify owner access returns.
  6. Archive tenant only after confirmation and verify data remains visible to superadmin.

Access Delegation

  1. Open /superadmin/access.
  2. Create SUPPORT/FINANCE/CONTENT/OPS platform admin.
  3. Verify limited role sees only allowed pages.
  4. Disable platform admin and verify login/session no longer works.
  5. Check audit logs after permission changes.
Superadmin + Student

Book-Based Syllabus Tracker

Superadmin Book Library

  1. Open /superadmin/syllabus.
  2. Click Download book template and verify XLSX downloads.
  3. Fill rows: bookTitle, author, className, subject, language, chapterTitle, chapterOrder, topicTitle, topicOrder, estimatedMinutes.
  4. Upload the XLSX through Import books.
  5. Verify book, chapter, topic counts update.
  6. Open the imported book, edit metadata, then publish it.
  7. Add a new chapter/topic later and confirm book update saves.

Student My Books

  1. Login as student and open /student/syllabus.
  2. Search the published book by title, author, subject, or class/exam.
  3. Click Add to My Books.
  4. Open the book and verify chapters/topics appear.
  5. Mark one topic In progress, then Complete.
  6. Open dashboard and verify book progress, topics today, and streak update.
  7. Open revisions and verify revision schedule was created.
  8. After superadmin adds a new topic, return to student tracker and verify Sync new topics appears.

Book Request Flow

  1. Student opens Study Tools or request missing book action.
  2. Submit book title, author/class/subject/message, and TOC image/PDF if available.
  3. Superadmin opens /superadmin/book-requests.
  4. Move request to IN_REVIEW.
  5. Create/import the global book from TOC.
  6. Paste global book id and click Link fulfilled book.
  7. Verify owner dashboard has no book request management flow.
Owner

Owner Operations

Admissions + Roster

  1. Create admission manually.
  2. Approve join request.
  3. Verify student appears in roster.
  4. Edit student details.
  5. Export roster/report if available.

Seat Map

  1. Open /owner/seats.
  2. If empty, create floor and add seat bank.
  3. Existing seats should show daily allotment first.
  4. Select student, select free seat, allot seat.
  5. Manage layout drawer: add rooms, templates, move/paint sections.
  6. Occupied seat should show occupant detail, not duplicate allot actions.

Attendance

  1. Open /owner/checkins.
  2. Header QR icon opens compact QR popup.
  3. Download QR creates PNG.
  4. Print poster still works from attendance page.
  5. Manual attendance works for owner/team users with access.
  6. Logs show 5-6 items first; rest scroll inside log area with name/date filter.
Owner + Superadmin

Plans, Payments, Coupons, Growth

Plans And Restrictions

  1. Superadmin opens plans/access settings.
  2. Edit trial and paid plan feature access.
  3. Verify owner plan page reflects live plan data.
  4. Trial library should follow configurable access, not hardcoded limits.
  5. Test 999/6-month and 449/2-month plans.
  6. Test referral bonus for paid onboarding.

Payments And Razorpay

  1. Verify Razorpay key and webhook settings are saved in superadmin integrations.
  2. Start owner plan payment flow.
  3. Complete test/live payment as configured.
  4. Confirm webhook updates subscription/payment status.
  5. Check failed/cancelled payment handling.
  6. Export payment reports.
Public

Landing, Marketplace, Listing, Website Builder

Landing + Blog

  1. Open landing page and verify header links remain visible.
  2. Verify Book Demo button appears when superadmin demo/support WhatsApp number exists.
  3. Verify floating WhatsApp opens configured support number.
  4. Open /blog and a blog detail page.
  5. Superadmin creates/edits/publishes/unpublishes a blog.
  6. Draft blog should not be publicly visible.

Marketplace + Subdomain

  1. Owner uploads logo, cover, gallery from listing/website builder.
  2. Verify marketplace card shows image, plans, offer, amenities.
  3. Open listing detail and verify CTA/contact actions.
  4. Open owner subdomain homepage.
  5. Click Home, Features, Gallery, Pricing, About, Contact and verify page content changes.
  6. Owner-specific WhatsApp floating button opens owner public WhatsApp number.
Student

Student App

Unified Scanner

  1. Click QR icon in student header.
  2. Scanner opens directly, not a long explanation page.
  3. Scan unjoined library QR: join request created.
  4. Scan joined library QR while outside: check-in.
  5. Scan again while inside: checkout.
  6. Invalid QR shows error inside scanner popup.

Study Zone

  1. Open My Library, Study Zone, Study Tools tabs.
  2. Focus mode starts/stops session.
  3. Revision dashboard shows due/completed/weak topics.
  4. Rewards/referrals pages load.

Payments + Library

  1. Student sees active library and seat.
  2. Payments page shows dues and recent payments.
  3. Notifications page shows owner broadcasts.
  4. Settings can update profile safely.
Mobile QA

Mobile View Checks

  1. Test Chrome mobile viewport around 360 x 800.
  2. Check owner dashboard, admissions, seats, attendance, settings, listing, website.
  3. Check student dashboard, scanner, syllabus, revisions, payments.
  4. Check superadmin syllabus and book requests.
  5. No bottom content should be hidden behind mobile nav.
  6. No horizontal scrollbar unless it is an intentional table/card strip.
  7. Tiles/cards should be compact; no huge empty white areas.
  8. Drawers/sheets should have visible close and submit buttons.
