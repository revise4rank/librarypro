Pre-flight

Build, Deploy, And Health

First run these checks. If these fail, do not continue with feature testing.
  1. Run npm.cmd run build locally.
  2. Run npm.cmd test locally.
  3. Deploy to Hostinger and run migrations if API/data changed.
  4. Verify https://api.booklib.in/health returns {"ok":true}.
  5. Open https://booklib.in, /owner/login, /student/login, /superadmin/login.

Auth

Login, Session, Password, Google

Role Login

  1. Owner login lands on owner dashboard.
  2. Student login lands on student dashboard.
  3. Superadmin login lands on superadmin dashboard.
  4. Refresh page and confirm login persists.
  5. Close browser and reopen; session should remain until logout.

Password/Google

  1. Password eye button works on every password input.
  2. Forgot password link is visible on all login pages.
  3. Google owner login does not land on student pages.
  4. Google student login does not land on owner pages.
  5. Disabled Google client error should not appear after config is enabled.
Owner

Owner Dashboard, Admissions, Roster

Dashboard Density
  1. Open owner dashboard on desktop and mobile.
  2. Check top actions are visible without long scroll.
  3. Switch dashboard tabs: Today, Pipeline, Insights.
  4. Cards should be compact; no huge empty tiles.
  5. Sidebar remains fixed and does not jump upward.
Admissions
  1. Create desk admission with no seat.
  2. Create desk admission with Floor -> Room -> Seat.
  3. Verify student appears in Active roster.
  4. Verify ledger entry is created.
  5. Verify auto referral code starts with BL.
Join Requests
  1. Student scanner creates join request for unjoined student.
  2. Owner opens Review join requests.
  3. Reject request button works from card and selected panel.
  4. Approve request with plan only.
  5. Approve request with Floor -> Room -> Seat.
Active Roster
  1. Open /owner/students.
  2. Roster student list should be compact rows, not tall cards.
  3. Long roster should scroll inside the roster box, not stretch whole page.
  4. Select student; right summary updates.
  5. Edit profile drawer, plan drawer, and manage seat drawer work.
  6. Open detailed student profile opens correct mapped student.
Owner Seats

Floor, Room, Seat Map, Seat Allotment

Correct flow: Create Floor -> Create Room with seat count -> Seats auto-create inside room -> Filter by floor/room/status -> Allot student.

Layout Flow

  1. Open /owner/seats.
  2. Click Manage layout.
  3. Verify button sequence: Floors, Rooms, Seats, Templates, Move/Paint.
  4. Create a floor.
  5. Create multiple rooms on same floor with different seat counts.
  6. Confirm room list shows only actual rooms, not seat labels like A1/A2.
  7. Seats created with room should appear in map and room filter.

Daily Seat Allotment

  1. Use floor filter; room dropdown should update by floor.
  2. Use room filter; map should show only selected room seats.
  3. Use status filter: All, Available, Occupied, Reserved, Blocked.
  4. Select unallotted student and free seat.
  5. Click Allot seat and verify roster/student profile updates.
  6. Occupied seat shows occupant detail, not allot action.

Student Planner

Daily, Weekly, Monthly Planner

Daily
  1. Add task with subject, topic, duration, priority, deadline.
  2. Complete task and verify today progress updates.
  3. Reschedule/carry forward incomplete task.
  4. Start timer/focus session and log minutes.
  5. Priority badges/colors visible.

  1. Add weekly goal.
  2. Click Generate daily tasks and verify tasks appear on weekly board.

Monthly
  1. Add monthly goal.
  2. Click Split into weekly goals and verify 4 weekly goals are created.
  3. Calendar markers and heatmap update.
  4. Add exam countdown.
  5. Monthly summary values make sense.

Widgets

  1. Sticky note colors are clickable and persist.
  2. Sticky note delete button works.

  5. Reminders toggle does not break page.

Mobile QA

Mobile Density, Bottom Nav, Drawers

Use Chrome DevTools 375px width or a real Android phone. Most BookLib problems show up on mobile first.
  1. Owner dashboard: top 2-3 actions visible without heavy scroll.
  2. Owner roster: active roster list scrolls inside its tile.
  3. Owner seats: floor/room filters and map are usable.
  4. Owner checkins: latest logs do not push page endlessly; filters are compact.
  5. Student planner: Daily/Weekly/Monthly tabs visible and usable.
  6. Student scanner: camera popup does not show extra error story below.
  7. All drawers/sheets have visible close and submit buttons.
  8. Bottom nav never hides last card/action.
